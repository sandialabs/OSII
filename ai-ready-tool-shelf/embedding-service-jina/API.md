# API.md

## Purpose

This document describes the HTTP API for the Jina embedding service. The service exposes a health endpoint and an OpenAI-compatible embeddings endpoint. It is intended to let another agent integrate, test, or extend the service without needing to inspect the implementation first.

## Base URL

Unless otherwise configured, the service listens on port `8050`.

Local development base URL:

```text
http://localhost:8050
```

## Endpoints

- `GET /health`
- `POST /v1/embeddings`

## Endpoint: `GET /health`

### Purpose

Returns a simple health payload indicating whether the service is up and whether the embedding model has been loaded.

### Request

```http
GET /health
```

### Response

Status code:

- `200 OK`

Response body:

```json
{
  "status": "ok",
  "model_loaded": true,
  "model": "jinaai/jina-embeddings-v2-base-en"
}
```

### Response fields

- `status`: string health indicator
- `model_loaded`: boolean indicating whether the model is initialized
- `model`: configured model identifier

## Endpoint: `POST /v1/embeddings`

### Purpose

Creates embeddings using an OpenAI-compatible request and response shape.

### Request

```http
POST /v1/embeddings
Content-Type: application/json
```

### Supported request body

```json
{
  "input": "text to embed",
  "model": "jinaai/jina-embeddings-v2-base-en",
  "encoding_format": "float",
  "dimensions": null,
  "user": "optional-user-id"
}
```

### Request fields

- `input`: required
  - may be a single string
  - may be a list of strings
- `model`: optional
  - if provided, it must exactly match the configured model name
  - current configured model is `jinaai/jina-embeddings-v2-base-en`
- `encoding_format`: optional
  - only `"float"` is supported
  - default is `"float"`
- `dimensions`: optional
  - currently accepted but ignored
- `user`: optional
  - accepted for compatibility
  - currently not used by the service

### Valid example: single string input

```json
{
  "input": "Embeddings map text into vector space.",
  "model": "jinaai/jina-embeddings-v2-base-en",
  "encoding_format": "float"
}
```

### Valid example: list input

```json
{
  "input": [
    "Sandia develops advanced national security technologies.",
    "Embeddings map text into vector space."
  ],
  "model": "jinaai/jina-embeddings-v2-base-en",
  "encoding_format": "float"
}
```

### Successful response

Status code:

- `200 OK`

Response body shape:

```json
{
  "object": "list",
  "data": [
    {
      "object": "embedding",
      "index": 0,
      "embedding": [0.123, 0.456, 0.789]
    }
  ],
  "model": "jinaai/jina-embeddings-v2-base-en",
  "usage": {
    "prompt_tokens": 0,
    "total_tokens": 0
  }
}
```

### Response fields

- `object`: always `"list"`
- `data`: list of embedding items
  - each item contains:
    - `object`: always `"embedding"`
    - `index`: zero-based item index
    - `embedding`: list of floats
- `model`: model identifier used to generate embeddings
- `usage`: token usage object
  - `prompt_tokens`: currently always `0`
  - `total_tokens`: currently always `0`

## Validation rules

The service applies the following validation rules:

- `input` must not be empty
- if `input` is a list, the list length must not exceed the configured maximum
- every item in `input` must be a string
- every string must contain non-whitespace content
- every string must not exceed the configured maximum character length
- if `model` is supplied, it must match the configured model name
- `encoding_format` must be `"float"`

### Current configuration defaults relevant to validation

- model name: `jinaai/jina-embeddings-v2-base-en`
- default batch size: `16`
- maximum batch size: `128`
- maximum texts per request: `128`
- maximum characters per text: `50000`
- default normalization: `true`

## Error behavior

The service returns JSON error responses generated by FastAPI.

Typical status codes:

- `400 Bad Request`
  - invalid input
  - unsupported encoding format
  - model mismatch
  - too many inputs
  - empty text
  - text too long
- `503 Service Unavailable`
  - model not yet loaded

### Example error response

```json
{
  "detail": "Only encoding_format='float' is supported"
}
```

## Model behavior

The service uses:

- `jinaai/jina-embeddings-v2-base-en`

Embeddings are generated on CPU.

The service currently normalizes embeddings according to server configuration. Another agent should assume normalized vectors unless the implementation is intentionally changed.

## OpenAI compatibility notes

This API is designed to be OpenAI-compatible in endpoint shape, but it is not a full clone of all OpenAI behavior.

Supported:

- `POST /v1/embeddings`
- string input
- list-of-strings input
- `model` field
- `encoding_format="float"`
- `user` field acceptance
- OpenAI-like response envelope

Not currently supported or only partially supported:

- authentication
- exact token accounting
- base64 encoding format
- output dimension reduction
- richer metadata

## PowerShell examples

### Health check

```powershell
Invoke-RestMethod -Method Get -Uri "http://localhost:8050/health"
```

### Embeddings request with list input

```powershell
$body = @{
    input = @(
        "Sandia develops advanced national security technologies.",
        "Embeddings map text into vector space."
    )
    model = "jinaai/jina-embeddings-v2-base-en"
    encoding_format = "float"
} | ConvertTo-Json -Depth 5

Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8050/v1/embeddings" `
    -ContentType "application/json" `
    -Body $body
```

### Embeddings request with single string input

```powershell
$body = @{
    input = "Embeddings map text into vector space."
    model = "jinaai/jina-embeddings-v2-base-en"
    encoding_format = "float"
} | ConvertTo-Json -Depth 5

Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8050/v1/embeddings" `
    -ContentType "application/json" `
    -Body $body
```

## cURL example

```bash
curl -X POST "http://localhost:8050/v1/embeddings" ^
  -H "Content-Type: application/json" ^
  -d "{\"input\":[\"Sandia develops advanced national security technologies.\",\"Embeddings map text into vector space.\"],\"model\":\"jinaai/jina-embeddings-v2-base-en\",\"encoding_format\":\"float\"}"
```

Note: the service is primarily documented with Windows and PowerShell examples. If another agent wants Unix shell examples, they should translate commands accordingly.

## Operational notes for another agent

- Assume port `8050` everywhere unless explicitly overridden.
- Do not introduce port `8000` in documentation, examples, scripts, or container runtime commands.
- If adding new examples, keep them Windows-friendly by default.
- If extending the API, preserve the OpenAI-compatible shape of `POST /v1/embeddings`.
- If exact token usage is needed, that must be implemented explicitly; current values are placeholders.
- If adding authentication, document whether it is OpenAI-style bearer auth or a custom mechanism.

## Suggested future extensions

If another agent is extending the service, the most likely next additions are:

- bearer token authentication
- exact or approximate token counting
- support for `encoding_format` alternatives
- support for optional non-normalized embeddings
- request logging
- rate limiting
- structured metrics
- Docker Compose support
- Kubernetes deployment manifests
